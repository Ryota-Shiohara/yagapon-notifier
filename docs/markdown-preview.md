# Markdown添付のプレビュー

サーバー内の全チャンネルへ `.md` ファイルを投稿すると、Botが本文をダウンロードして保存し、元投稿に「📄 ファイル名 をプレビュー」リンクボタンを返信します。本文なし・大文字の `.MD`・複数添付に対応し、Markdown添付1件につき1つの返信を送ります。`.txt` や `.md.exe` など、`.md` 以外の添付は処理しません。メンション応答・文字列トリガー・`!ping` は従来どおり独立して動作します。

## 公開範囲

**URLを知っている人はDiscordへのログインなしに閲覧できます。ランダムURLはDiscordの閲覧権限を再現しません。** 全チャンネルを処理する仕様のため、権限限定チャンネルのMarkdownも同じ公開範囲になります。

機能の初期状態は無効です。有効化時はBotが投稿を受信できるサーバー内の全チャンネルが対象です。権限限定チャンネル、参加済みのスレッド、ボイスチャンネル内のテキストも含みます。DMとBot自身を含むBot投稿は対象外です。`MARKDOWN_PREVIEW_CHANNEL_IDS=*` が既定値で、必要に応じてチャンネルIDをカンマ区切りで指定して範囲を絞れます。HTTPSの公開オリジンが必要です。

投稿後のチャンネル権限変更・元投稿削除に合わせたリンク失効は行いません。既存リンクは期限まで有効です。緊急時は機能を無効にして再起動すると全プレビュールートを停止できます。個別削除は保存ディレクトリの該当UUIDのJSONファイルを削除してください。削除したリンクは404になります。

## 有効化

現在のCompute Engine VMとDocker Compose、既存の `./data:/app/data` マウントを利用します。新規サーバーやR2は不要です。

`.env` の設定例（実際の公開ドメインに置き換えます）:

```env
MARKDOWN_PREVIEW_ENABLED=true
MARKDOWN_PREVIEW_PUBLIC_URL=https://your-public-domain.example
MARKDOWN_PREVIEW_CHANNEL_IDS=*
MARKDOWN_PREVIEW_MAX_FILE_BYTES=1048576
MARKDOWN_PREVIEW_MAX_TOTAL_BYTES=104857600
MARKDOWN_PREVIEW_MAX_FILES=1000
MARKDOWN_PREVIEW_TTL_MS=604800000
MARKDOWN_PREVIEW_DOWNLOAD_TIMEOUT_MS=10000
MARKDOWN_PREVIEW_CLEANUP_INTERVAL_MS=3600000
```

`MARKDOWN_PREVIEW_PUBLIC_URL` はパス・クエリ・認証情報なしのHTTPSオリジンです。HostヘッダーやDiscord添付URLから公開URLを生成しません。ローカル開発時の保存先は `MARKDOWN_PREVIEW_STORE_PATH=data/markdown`、Composeでは `/app/data/markdown` に固定します。

既存のCloudflare Tunnel公開ホストが `http://bot:3000` に向いていれば `/preview/<UUID>` も同じアプリへ到達します。外部のAccess設定やパス制限がある場合は管理者が確認してください。実環境のドメイン・トンネル稼働状況はこの実装では検証していません。DiscordのBotには対象チャンネルの閲覧・メッセージ送信権限が必要です。

運用担当者が通常の更新手順で反映した後、Markdown投稿で確認してください。この変更作業ではpush・デプロイは行いません。

## 保存・容量管理

- 既定は1ファイル1MiB、保存ディレクトリ100MiB、最大1,000件、7日間です。容量はJSONのメタデータ・本文のエスケープ増加・原子更新用の一時ファイル予約を含みます。上限に達すると新規保存を拒否し、有効なリンクを容量確保のために削除しません。
- UUID v4を保存名とURLに使います。元ファイル名やDiscordのIDをパスとして扱いません。本文と元ファイル名、投稿日時、guild/channel/message/attachment ID、有効期限、返信IDを1つのJSONに保存し、原子的に更新します。署名付き添付URLは保存しません。
- 起動時と1時間ごと、保存処理時に期限切れを削除します。アクセス時点で期限切れなら410、その後のアクセスや自動削除後は404です。停止中は削除されず、次の起動で回収します。本文と返信履歴はコンテナ再起動後も残ります。
- 同一添付は保存済みの返信IDで重複を抑止し、並行イベントも直列化します。送信失敗時は既存のプレビューURLと決定的nonceで再試行できます。Discord送信直後・返信ID保存直前に停止した場合、Discordのnonce重複検出期間を超えると重複返信する余地があります。履歴の保持期間はプレビューと同じです。
- 単一Botプロセスでの運用を前提とします。複数プロセスで同じ保存先を共有しないでください。待機中の投稿は最大50件とし、超過時はログを記録して処理を見送ります。失敗した投稿を自動で定期再試行する機能はありません。
- `data` の書込権限を起動時に確認します。VM上でBot実行ユーザーがディレクトリを書き込めるようにしてください。VM削除によるデータ消失はMVPで許容します。復元が必要なら運用側で `data/markdown` をバックアップしてください。

## 表示と安全対策

見出し・リスト・表・引用・コードブロック・強調・HTTP(S)/メールリンクを表示します。スマホ幅に合わせた余白、コードと表の横スクロール、OSのダークモードに対応します。

生HTMLは文字列として表示し、変換後のHTMLも許可タグ・属性のみ残します。JavaScript/data URL、相対リンク、Discord CDN添付リンクを無効化します。画像は外部アクセスによる追跡を避けて代替テキストだけを表示します。CSPでスクリプト・外部リソース・埋め込みを禁止し、リファラー送信、キャッシュ、検索インデックス登録を抑止します。Mermaid・数式・画像・相対ファイル参照はMVP対象外です。

ダウンロード先はDiscord CDNのHTTPS添付パスに限定し、リダイレクトを許可しません。宣言サイズと実際に取得したバイト数を両方制限し、タイムアウトはレスポンス本文取得まで適用します。不正UTF-8、HTTPエラー、容量超過、保存・送信失敗時に不正なリンクを返信しません。エラーログにはイベント名とDiscord IDだけを出し、本文や署名付きURLは出しません。他の添付や既存トリガーは引き続き処理します。

## 確認手順

`npm test` で添付のみ・本文あり・全チャンネル・権限限定チャンネル・スレッド・非md・任意の対象制限・複数添付・特殊文字の名前・大容量・ダウンロード失敗・無効ID・期限切れ・保存先再読込・悪意あるMarkdownと既存APIの回帰を確認します。

本番有効化時には、Markdownを投稿し、PCとiPhone等の公式Discordアプリからボタンを開いてください。コンテナ再起動後も有効期限内のリンクが開くこと、md以外の添付に返信されないこと、既存通知APIとコマンドが動くことも確認してください。
